# 제안과 단가 협상

- 제안은 대리점이 계약 요청에 제출하는 단가와 서비스 조건이다.
- 제안은 해당 화주에게만 공개하고 다른 대리점에는 공개하지 않는다.
- 한 대리점은 하나의 계약 요청에 하나의 제안을 가진다.
- 대표 단가와 배송 품목 라인별 단가를 함께 둘 수 있다.
- 최종 계약은 합의된 품목 라인별 단가를 우선 사용한다.

## 협상 이벤트

- 실시간 채팅이 아니라 Proposal 단위 협상 이벤트 원장으로 관리한다.
- 이벤트는 `proposalId`와 순번으로 정렬한다.
- 응답 대기 이벤트는 제안당 최대 하나다.
- 이벤트 작성자는 자기 이벤트를 수락·거절할 수 없다.
- 수락 시 제안의 현재 단가와 품목별 단가를 갱신한다.
- 거절 시 기존 제안 단가를 유지하고 대기 상태만 해제한다.

## 동시성

- 협상 이벤트 등록 시 Proposal 행을 짧게 잠근다.
- 순번과 대기 이벤트 검증을 같은 트랜잭션에서 수행한다.
- 최종 계약 생성 후 신규 제안·수정·협상을 막는다.
- RDB가 단가와 상태의 원천 저장소다.
